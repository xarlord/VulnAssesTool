## Orchestrator-verified critical findings

Two Must-Have findings were re-verified directly (not just audit-flagged) and are **confirmed real**:

1. **FR-04.3 CVSS breakdown is broken (CONFIRMED BUG).** `parseCvssVector()` ([src/renderer/lib/cvss/parser.ts:78](../../src/renderer/lib/cvss/parser.ts#L78)) returns `null` for every valid CVSS 3.1 vector. `parseMetricValue` maps only `'S'→'scope'`; for all other prefixes (`AV`/`AC`/`PR`/`UI`/`C`/`I`/`A`) it looks up `CVSS_METRIC_VALUES['AV']` etc., but the map is keyed by full names (`attackVector`…). The first metric (`AV`) throws → caught → `null`. Verified by direct execution against two real vectors (both returned `null`). Undetected because there is no `lib/cvss/parser.test.ts` and the CVSS UI components consume pre-parsed props in their tests. **Fix: map each prefix to its full-name key in `parseMetricValue` (~5 lines) + add `parser.test.ts`.** Callers: NvdCveDetailModal, nvdProvider, osvProvider.

2. **FR-07.1/07.2 Audit trail is largely unwired (CONFIRMED GAP).** The audit logger library is solid (146 unit tests pass), but it is invoked **only** by `falsePositiveFilter.ts`; project CREATE/UPDATE/DELETE (in `useStore`), scans, SBOM import, export, and settings changes never call it, and the server has no general audit path (only `fpfAudit.sql`). The compliance audit trail the PRD requires is therefore not connected to the actions it must record. **Fix: invoke the logger from the mutation/action code paths (store + server routes).**
