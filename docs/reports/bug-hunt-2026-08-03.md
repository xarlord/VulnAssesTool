## Critical (6)

### C1. RPM container packages silently dropped — `mock-on-live`

[server/services/ContainerService.ts:615](server/services/ContainerService.ts#L615)
`parseRpmPackages()` is a hardcoded stub returning `[]`. `scanLayerForPackages()` detects an rpm
DB, calls it, and pushes the empty result with **no** `layerWarnings` entry — so RHEL/CentOS/Fedora
images report zero packages and look fully scanned.
**Fix:** implement RPM parsing (`rpm --dbpath … -qa`, or parse the rpmdb) or at minimum push a
`layerWarnings` entry so incomplete coverage is honest.

### C2. FPF audit trail never persisted — `mock-on-live`

[src/renderer/lib/services/fpf/filterAuditLogger.ts:227](src/renderer/lib/services/fpf/filterAuditLogger.ts#L227)
`logEvent()` no-ops when constructed without a `Database`, and the sole production call site
([FalsePositiveFilter.tsx:202](src/renderer/pages/FalsePositiveFilter.tsx#L202)) passes none. Every
filter decision skips persistence while `getAuditLog()`/`verifyIntegrity()` return empty/"valid" —
looking like a clean, verified ISO-21434 audit trail rather than a missing one.
**Fix:** wire a real DB (or server audit endpoint) into `new FalsePositiveFilter(config, db)`, and/or
make `logEvent`/`verifyIntegrity` warn/throw when no backend is configured.

### C3. Delta sync infinite loop on large windows

[server/database/nvd/nvdDeltaSync.ts:278](server/database/nvd/nvdDeltaSync.ts#L278)
`syncFromDate` is computed once and never advanced; the outer `while (hasMore)` re-calls
`fetchModifiedSince` with the identical date window. If >50,000 CVEs changed, it re-fetches the same
~50k every iteration and `truncated` stays true forever — hammering NVD, never completing.
**Fix:** advance the window to the last received CVE's `lastModified` between iterations, or use a
resume cursor instead of restarting at `startIndex=0`.

### C4. Backup restore error masked by finally

[server/routes/backup.ts:95](server/routes/backup.ts#L95)
`initializeDatabase()` runs in a `finally` after `closeDatabase()`. A throw in `finally` discards the
in-flight restore exception, so the client only ever sees a reinit error; if reinit itself throws, the
DB is left closed.
**Fix:** capture the restore error explicitly; wrap the `finally` reinit in its own try/catch; always
surface the original restore failure.

### C5. KEV cache never refreshes after first build

[server/services/intelligence/KevService.ts:396](server/services/intelligence/KevService.ts#L396)
`buildCache()` calls `getAllKevIds()`, which short-circuits and returns the existing Set when
`kevCache` is non-null. After `initialize()`'s first build, later `syncFromCisa()` → `buildCache()`
is a no-op, so `isKev()` never reflects newly-added CVEs until restart.
**Fix:** in `buildCache()`, query the DB directly (or `kevCache = null` first) to force a rebuild.

### C6. NVD downloader targets a feed URL that never existed

[server/database/nvd/multiThreadedDownloader.ts:140](server/database/nvd/multiThreadedDownloader.ts#L140)
`buildFeedUrl()`/`buildChecksumUrl()` build `feeds/json/cve/2.0/nvdcve-2.0-{year}.json.gz` — a path
NVD never published (versioned JSON feeds were `1.1`/`1.0`, since retired). Reachable via
`POST /sync/start`; every year download 404s.
**Fix:** point at the REST API v2.0 (as `nvdApiV2Client.ts` already does) or remove this dead
downloader and route `/sync/start` through `NvdApiV2Client`/`NvdDataImporter`.

### H7. Bulk import "transaction" cannot roll back

[server/database/nvd/bulkDatabase.ts:170](server/database/nvd/bulkDatabase.ts#L170)
`begin/commit/rollbackTransaction` only buffer in a JS array; commit does real per-row upserts;
rollback clears memory and issues **no SQL ROLLBACK**. A mid-batch failure leaves partial rows
persisted while the whole batch is counted failed.
**Fix:** wrap each batch in a real `db.transaction(fn)()`.

### H8. TOCTOU race on `/sync/bulk`

[server/routes/database.ts:668](server/routes/database.ts#L668)
Checks `syncState.isSyncing`, then `await`s an API-key lookup, then calls `beginSync('bulk')` — two
concurrent requests both pass the check before either sets the flag, both write to SQLite.
**Fix:** call `beginSync('bulk')` synchronously before the first `await` (as `/sync/start` and
`/sync/delta` do); roll back if the key check fails.

### H9. Shared rate-limiter instances across unrelated route groups

[server/app.ts:74](server/app.ts#L74)
`defaultLimiter`/`containerLimiter` are module-level singletons mounted on 6 and 2 route groups; the
IP-only key means all those routes share one 60-req/min bucket — traffic on one feature throttles
others.
**Fix:** a `makeDefaultLimiter()` factory invoked per mount.

### H10. Attack graph conflates "unmodeled" with "unreachable"

[src/renderer/lib/services/fpf/attackGraph.ts:261](src/renderer/lib/services/fpf/attackGraph.ts#L261)
`isReachableFromExternal()` returns `confidence:100` unreachable when no node matches the component
at all — so Tier 2 auto-suppresses medium/low vulns for any component outside the hardcoded
interface/service map.
**Fix:** return low/neutral confidence or a distinct "unknown" so callers don't auto-filter unmodeled
components.

### H11. Version-mismatch filter suppresses across release branches

[src/renderer/lib/services/fpf/tier1QuickFilter.ts:225](src/renderer/lib/services/fpf/tier1QuickFilter.ts#L225)

branch — e.g. `2.0.0` with `['1.2.5','2.3.1']` is suppressed because it beats the 1.x fix.
**Fix:** compare only against same-branch fixes, or use `affectedVersionRanges`.

### H12. High-severity findings bypass the escalation guard

[src/renderer/lib/services/fpf/tier1QuickFilter.ts:87](src/renderer/lib/services/fpf/tier1QuickFilter.ts#L87)
Escalation uses `confidence < 95`, but `checkSuppressionRules()` and the fixed-version branch hardcode
exactly `95`, and default `neverAutoFilter` is `['critical']` only — so a HIGH matching either rule is
auto-filtered with no review.
**Fix:** use `<= 95` (or adjust the hardcoded confidences / cutoff).

### H13. WebSocket subscriptions return a no-op unsubscribe (listener leak)

[src/renderer/lib/platform/serverAdapter.ts:91](src/renderer/lib/platform/serverAdapter.ts#L91)
`onSyncProgress/Complete/Error`, `onBulkDownloadProgress`, `onKevSynced`, `onScanProgress`,

Callers (e.g. [Search.tsx:162](src/renderer/pages/Search.tsx#L162)) call it on unmount, so stale

### H14. Onboarding tour never records completion/skip
